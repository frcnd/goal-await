# Goal-await AI 安装与使用指南

[English](AI_GUIDE.md) | **简体中文**

这是一份由用户主动交给 AI 的操作参考，不是开始目标、修改环境或扩大业务权限的授权。AI 应先读当前请求、[README](../README.zh-CN.md) 和适用的安装说明；用户明确要求安装或使用 Goal-await 时，按这里的边界执行，并保留对话中已经给出的授权。

本文不能替代已安装的 Skill。运行时读取安装位置中的 `SKILL.md`，调用其当前脚本和动作格式；不要另建状态机、定时器、守护进程或平行 hook。

## 判断授权与缺失信息

- 用户只递来本文时，解释能力并询问是否执行；这不表示用户已同意安装或启动目标。
- 用户请求“安装”：安装范围（用户级或项目级）及确切目标路径能从当前请求和上下文确定时，直接审核计划、安装、核对信任并重载，不机械地逐项复问。
- 安装范围、确切目标路径等必要信息无法确定时，集中询问缺少的信息。用户已授权范围内的下一步工作无需反复确认。
- 用户请求“开始/继续目标”：保留已有授权和已完成的业务工作，按原目标推进。安装范围不扩大文件、账号、远端作业或发布权限。
- 用户改变范围、要求付费资源、向他人发消息或执行新的外部写入时，以该动作是否已获当前用户授权为准；不要从前文推断无关授权。

## 选择安装范围

先识别目标：同一账户多个项目共用，选用户级；只为准确项目启用，选项目级。两者不要同时启用同名 Skill，因为 Stop hook 会叠加。项目级细节见 [PROJECT_INSTALL](PROJECT_INSTALL.zh-CN.md)，用户级完整流程见 [README](../README.zh-CN.md)。

核对下载目录中的安装器、Python 3.11+、目标路径、写入权限、现有 `.agents/skills/goal-await` 和安装记录。真实桌面使用应与计划选择的用户目录、`CODEX_HOME` 和 shell 一致。Windows CMD 宿主在预览和安装时都使用 `--hook-shell cmd`；PowerShell 使用默认值。

先运行相应 `plan` 并读取 JSON。向用户展示会写入的准确路径和 Stop 定义；若用户已授权且计划无冲突，再执行 `install`。不要通过改配置文件、复制安装副本或新增第二条 hook 绕过安装器的范围检查。

安装后仍需要原生信任。项目级在目标项目执行 `/hooks`，核对项目来源中的逐字 Stop；只有项目级可按 [PROJECT_INSTALL](PROJECT_INSTALL.zh-CN.md) 使用 `tools/trust.py`。用户级必须使用用户配置来源的 `/hooks`，不能把项目辅助工具当作用户级信任入口。只信任计划中的这一条，随后新建空闲对话或正常重载；不要把进程 reload 当成桌面已重载。

默认允许 Skill 隐式调用，因此通常不修改源 YAML。用户明确要求关闭隐式调用时，按 README 的 `allow_implicit_invocation: false` 说明修改**源码** `skill/goal-await/agents/openai.yaml`：首次安装前修改；已安装时先暂停目标，在原生界面确认任务停止，用原安装器卸载，再修改源码并安装。不要直接改安装副本，否则文件校验值与安装记录不符，卸载会被拒绝。

按所选范围的安装文档完成操作后，报告实际写入位置、备份位置及信任和重载的完成情况。安装成功时不要顺手启动目标；启动需要用户对明确业务目标的请求。

## 运行 Goal-await

安装并重载后，用户已要求推进明确目标且当前调用策略允许时，AI 可以主动选择 Goal-await，不要求用户每次点名。仅阅读本文、讨论能力或安装成功不会自动开始目标。`$goal-await` 是 Skill 调用，不是新增的内置 `/goal`。

结合当前上下文明确目标、输入、预期产物、验收标准和资源预算，然后读取已安装的 `SKILL.md` 执行。开始、等待、暂停、恢复和完成的具体动作由 Skill 定义，本文不另设运行流程。

只推进当前对话已授权的目标，尊重用户暂停和中断。不要扫描、改写或重启其他对话的目标；完成前核对整个目标的验收证据。仅写入本地状态不代表原生定时操作成功，应核对真实工具回执。

Stop 自动接续前，读取本轮业务工具活动。文件改动、命令执行和有效工具结果可以支持继续调查；计划文字、状态复述、Goal-await 控制记账和已有 hook 反馈不算进展。只有文字的手工轮次可得到一次纠正性接续；之后仍无新活动时，停止自动接续并转入复查。计划模式或存在可见等待时不追加催促。继续提示保留完整目标，每个宿主轮次仍最多三次接续。工具活动只用于判断能否继续，不能证明完整目标已经通过验收。

## 异常中断恢复

新目标使用 Skill 的开始流程并加入 `--recover-errors`；这是 Skill 的默认动作，CLI 本身仍需显式启用。默认最多恢复两次、间隔两分钟，可用 `--recovery-max-attempts`（1 至 5）和 `--recovery-interval-minutes`（1 至 60）调整。若开始时无法识别受支持的活动对话记录，应停止并说明未启用恢复。

执行返回的每个原生定时 effects，并核对工具回执后才能说定时任务已就绪。首次创建时从原生工具结果读取实际 ID，只绑定这个 ID。异常恢复和后续等待共用同一 ID 与一次性 `RDATE` 调度。acknowledge 返回定时 effects 时也要执行。JSON 中的续跑内容在 acknowledge 命令返回 `accepted: true` 前只是待办；获准后先更新定时任务，再执行业务。不要向当前对话发送消息，也不要创建第二条定时任务。

恢复只接受脚本识别的完整 `max_output_tokens` 终止消息或两条完整的响应流提前断开消息。它不按经过时间推断失败，也不任意重新提交业务作业。门禁会核对原对话与工作目录、自动化标记、前后业务轮次、用户中断、剩余次数和接续确认。继续时依据已落盘产物和最新上下文，先核对副作用，只做尚未完成的工作。

模型选择仍由宿主及用户配置决定。手动切换或宿主回退后，等待检查、接续确认和有限次异常恢复都可继续，无需重新绑定目标，也不会重置剩余恢复预算；记录的模型仅作诊断信息。用户中断、未知错误、记录缺失或格式不受支持、次数用完或接续未确认时，都要停止恢复。若所选模型在首次恢复准入或下一次单次唤醒预约之前失败，应报告这次唤醒已消耗，并请用户手动继续。

旧 RUNNING 目标经人工恢复后，在同一业务对话调用 `recovery-enable` 并执行返回的 effects。缺少恢复字段的旧目标保持原有行为。从较早版本升级前先暂停目标与原生定时任务，卸载当前安装，再安装并重载 `0.3.1-preview`。不要声称旧目标会自动重启；它们不会。

## 安装冲突

项目级与用户级同时存在、同一项目有来源不明的同名 Skill、或安装记录与准确 hook 不匹配时，先停止相关目标并保留现场。确定由哪个安装器创建后，由该安装器卸载；不要用强制删除或改写 hash 来绕过保护。

## 诊断边界

`status` 返回 `active: false` 只表示当前对话尚未绑定目标，不是安装失败。若用户已明确要求开始且目标清楚，可调用安装的 `start`；否则说明需要用户确认要推进的目标。

判断命令结果时同时看退出码、stdout JSON 和 stderr。Windows 出现 `Failed to find real location of ...` 且退出码为 0、JSON 有效时，不应据此判定解释器不存在。非零、缺少预期字段或 JSON 含 `error` 时，再检查准确路径、UTF-8、权限、安装范围、安装记录与 hook 定义，并保留原始错误。

Stop hook 明确报告失败时，不声称自动接续成功。先检查当前对话是否有有效绑定、hook 是否已加载、准确定义是否已信任，以及状态目录是否可写；需要权限时使用宿主正常审批，限于该目录。

处理异常恢复时，要区分真正获准的接续和宿主仅仅发出的请求。原生任务成功创建或更新必须有实际回执和绑定；核对门禁结果、执行 ACK effects，并在业务继续前确认 `accepted: true`。用户中断、记录格式不受支持、次数用完或一次性唤醒已消耗都应作为停止条件报告，不能据此宣称业务目标失败。

`install.py uninstall` 拒绝修改过的安装副本或缺失/重复的本包 Stop 是保护措施；保留现场并核对来源，不要强制删除。用户级与项目级同时出现时，先核对并卸载不再使用的安装，不要做双重启动。

支持范围和使用限制见 [README](../README.zh-CN.md)。针对本次操作核对实际结果，不把文件复制成功或人工继续当作原生自动接续成功。
